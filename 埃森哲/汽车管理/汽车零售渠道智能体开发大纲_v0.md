# 汽车零售渠道管理智能体 · 开发大纲（V0.1 初稿）

> 起草：2026-09-12 晚 ｜ 目标：9月13日集中完善定稿
> 定位：面向 4S 店（经销商）的智能体工具，服务管理层 + 销售顾问两类角色
> 核心功能：线索跟进、试驾预约
> 数据来源：经销商录入 + 垂媒/自媒体 API + 厂商 API（三源融合）

---

## 1. 项目概述

### 1.1 背景与痛点

- 传统 4S 店线索依赖人工分配、Excel 跟单，响应慢、跟进不规范、流失率高
- 管理层缺乏实时数据视图，业绩归因靠月底报表，管理滞后
- 代理制模式转型期，经销商对精细化运营工具的需求上升（可与 DBA 研究衔接）

### 1.2 产品定位

- **服务对象**：经销商（4S 店）管理层为核心决策用户，销售顾问为高频操作用户
- **产品形态**：一套智能体系统，两个界面
  - 管理层界面（管理驾驶舱）：看数据、管分配、控质量
  - 销售顾问界面（个人工作台）：接线索、记跟进、约试驾
- **核心价值**：线索不流失、跟进不超时、试驾有调度、管理有依据

### 1.3 边界（本期不做）

- 不做 DMS 全功能替代（库存、财务、售后工单等不在范围）
- 不做面向消费者的购车 App（仅内部工具，客户触达通过短信/企微）
- 不做自动外呼（合规风险，仅辅助人工）

## 2. 用户角色与界面设计

### 2.1 角色与权限

| 角色        | 权限要点                |
| --------- | ------------------- |
| 店总/总经理    | 全店数据看板、预警总览、只读为主    |
| 销售经理/展厅经理 | 线索分配、调配、顾问监控、试驾资源管理 |
| 销售顾问      | 本人线索池、跟进记录、试驾日历     |
| 系统管理员     | 账号、字典、规则配置          |

### 2.2 管理层界面（管理驾驶舱）

1. **今日概览**：新增线索数、待跟进数、今日试驾数、今日到店数、预警数
2. **线索漏斗**：线索 → 有效 → 意向 → 邀约到店 → 试驾 → 订单 → 成交（各环节转化率）
3. **顾问工作台监控**：响应速度排名、跟进及时率、人均在手线索、试驾率
4. **预警中心**：
   - 线索超时未首触（>15 分钟）
   - 跟进超期（按意向等级的 SOP 时限）
   - 今日试驾爽约预警
   - 线索即将掉公海提醒
5. **试驾资源总览**：试驾车状态（可用/占用/维保）、今日/明日预约排期==（销售顾问根据客户预约进行试驾日程排程，体现为试驾排程表）==

### 2.3 销售顾问界面（移动端优先）

1. **今日待办**：需跟进客户列表（按紧急度排序）、今日试驾安排
2. **客户列表**：我的线索（按意向等级分组，掉公海倒计时显示）
3. **客户详情页**：基础信息 + 历史跟进记录 + 关注车型 + AI 建议（下一步动作/话术）
4. **快捷跟进**：跟进记录一键模板、语音转文字、拍照留档
5. **试驾日历**：我的预约时间线，一键发起预约

## 3. 核心模块一：线索跟进

### 3.1 线索接入==（垂媒/厂家系统API不能开放时需要销售顾问手动输入客户信息或标准格式表格批量导入）==

- 渠道对接：汽车之家、懂车帝、易车、抖音本地推、官网表单、企微留资、门店自然到店登记
- 统一线索模型：来源、车型意向、预算区间、留资时间、备注
- 去重规则：手机号为唯一键，30 天内重复留资合并（保留最新意向）

### 3.2 线索池与分配机制

- **公海/私海**：新线索进公海 → 按规则分配 → 顾问私海==（建立属于经销商自己的客户线索池。所有新增线索通过各渠道汇总到门店私有数据池，通过ai帮助进行线索梳理）==
- 分配规则（可配置）：
  - 轮询均分（默认）
  - 按顾问擅长车型定向分配
  - 管理层手动指派（大客户/特殊线索）
- **回收机制**：超过 N 天未有效跟进 → 自动掉回公海，他人可抢（防止线索沉淀在个人手里）
- 管理层可一键改派（顾问请假/离职场景）

### 3.3 跟进流程 SOP（可配置引擎）

| 意向等级        | 定义              | 首次响应   | 跟进频次    |
| ----------- | --------------- | ------ | ------- |
| H（7日内购车）    | 主动询价、到过店、指定车型配置 | ≤15 分钟 | 每 2 天   |
| A（30日内）     | 明确车型、比较中        | ≤30 分钟 | 每 3–5 天 |
| B（3个月内）     | 泛意向、价格敏感        | ≤2 小时  | 每周      |
| C（3个月以上/观望） | 仅留资浏览           | 当日     | 每两周     |

- 状态机：新建 → 已首触 → 跟进中 → 已邀约 → 已到店 → 已试驾 → 已订/成交 / 战败（战败原因必选：价格/竞品成交/放弃购车/无法联系/其他）
- 战败线索进公海池，30 天后可被重新激活（行业惯例：战败客户冷却期）

### 3.4 AI 辅助能力（智能体核心增值）==（对进入线索池的数据进行智能分析，降低人工判定的错误率，提高工作效率）==

1. **线索质量评分**：基于来源渠道、留资完整度、交互行为，输出 S/A/B/C 分级建议
2. **意图识别**：判断客户类型（急购型/比价型/观望型），提示应对策略
3. **跟进时机建议**：预测最佳联系时段（结合历史接通率）
4. **话术助手**：邀约到店、试驾邀约、异议处理（价格贵/再考虑/竞品对比）模板 + 个性化生成
5. **晨会日报**：自动生成门店日报（昨日漏斗变化、今日待办焦点、需管理层介入事项）

### 3.5 数据沉淀（服务管理与研究）

- 全过程留痕：每次触达时间、方式、内容摘要
- 行为数据结构化：为管理层考核与渠道研究提供底层数据（可衔接代理制论文的渠道行为分析）

## 4. 核心模块二：试驾预约

### 4.1 试驾车资源管理

- 试驾车台账：车型、牌照、保险、维保状态、负责人
- 可用性规则：维保中/保养到期自动锁定
- 时段管理：按 30/60 分钟粒度设置可预约时段（考虑清洁、充电/加油准备时间）

### 4.2 预约流程

1. 发起：顾问在客户详情页一键发起（选择车型/时段/试驾类型）
2. 冲突检测：同车同时段唯一，自动推荐空闲时段
3. 确认通知：短信/企微发送客户（含时间、地点、携带证件提示）
4. 提醒机制：
   - T-1 天：客户提醒 + 顾问准备提示
   - 当日：试驾车准备检查单（电量/油量/清洁/证件）
5. 试驾类型：到店试驾 / 上门送车试驾 / 深度试驾（过夜，需管理层审批）

### 4.3 试驾后闭环

- 试驾记录：客户反馈（满意度、关注点、异议）结构化录入
- 自动触发后续跟进任务（24 小时内回访）
- 爽约处理：记录爽约原因，自动进入二次邀约流程

### 4.4 转化分析

- 关键指标：线索→试驾转化率（行业参考 8%–15%）、试驾→订单转化率（30%–40%）、爽约率
- 按车型/渠道/顾问多维拆解

## 6. 技术架构（概要）

```
┌─────────────────────────────────────────────┐
│  管理层界面（Web 驾驶舱）   销售顾问界面（移动端）  │
├─────────────────────────────────────────────┤
│  业务中台：线索引擎 │ 分配引擎 │ 试驾调度 │ 规则配置  │
├─────────────────────────────────────────────┤
│  AI 服务层：评分 │ 意图识别 │ 话术生成 │ 日报生成   │
├─────────────────────────────────────────────┤
│  数据层：业务库 │ 行为日志 │ 数据仓库（分析）        │
├─────────────────────────────────────────────┤
│  集成层：线索平台 API │ 企微 │ 短信 │（可选）DMS    │
└─────────────────────────────────────────────┘
```

- 部署建议：云端 SaaS（多门店可扩展），客户手机号加密存储
- 模型接入：通用大模型 API + 汽车零售领域提示词工程（话术需管理层审核库）

### 6.3 数据来源架构（三大来源）

按数据主导权与接入方式，分为三类输入源，三者最终归一到统一的「线索/客户主数据模型」：

```
┌────────────────────────────────────────────────────────┐
│                     数据输入层                          │
├────────────┬────────────────┬──────────────────────────┤
│  来源1     │  来源2          │  来源3                   │
│ 经销商录入 │ 垂媒/自媒体 API │ 厂商 API                 │
└────────────┴────────────────┴──────────────────────────┘
                          ↓
            ┌────────────────────────────┐
            │ 统一线索/客户主数据模型     │
            │ (去重 / 合并 / 标准化)      │
            └────────────────────────────┘
                          ↓
              业务中台 + AI 服务层
```

#### 来源 1：经销商人工录入（**内生数据**）

- 录入主体：销售顾问、展厅前台、客服
- 录入场景：
  - 自然到店客户登记（前台扫码填表）
  - 电话咨询留资
  - 跟进过程记录（沟通内容、意向变化）
  - 试驾反馈录入
  - 战败原因归类
- 录入方式：移动端表单 + 语音转文字 + 拍照留档（名片、合同）
- 关键字段：客户信息、关注车型、预算、跟进记录、意向等级、试驾结果
- **数据特点**：颗粒度最细、价值最高，但依赖顾问录入质量——所以「录入激励机制」（如每次有效记录 +积分影响排行榜）要设计进产品

#### 来源 2：垂媒 + 自媒体 API（**外部引流数据**）

- **垂直媒体（垂媒）API**：
  - 汽车之家（销售线索 API）、懂车帝、易车
  - 字段：留资客户基本信息、关注车型、留资时间、来源 URL、留资表单字段
  - 接入方式：API 实时拉取或 webhook 推送 + 每日对账
- **自媒体/内容平台 API**：
  - 抖音本地推/企业号、微信视频号、快手
  - 留资线索 API + 私信消息回调
  - 内容互动数据（点赞、评论、私信关键词）作为线索质量评分补充信号
- **数据特点**：量大、来源标注清晰，但「线索—成交」归因链路长——需要在主数据中保留 `lead_source_channel` 字段以便全链路追踪

#### 来源 3：厂商 API（**官方权威数据**）

- 主要数据维度：
  - **车型库**：官方配置表、价格、促销政策、库存（决定能否给客户准确报价）
  - **订单/交付数据**：店内订单状态、交付进度、发票信息（用于售前售后打通）
  - **试驾车资源**：厂商下发的试驾车辆台账、保险、维保记录
  - **金融政策**：官方贴息、贷款方案（用于 AI 智能报价与对比）
  - **市场活动**：厂商发起的促销活动、任务（影响线索分配优先级）
- 接入方式：各品牌厂商的 DMS/CRM 开放接口（如上汽大众 VW-Agent、宝马 DealerSocket、比亚迪经销商 App 等），需要按品牌分别适配
- **数据特点**：权威但异构（不同厂商数据模型差异大），需要建立「厂商适配层」做协议转换

#### 三类数据融合后的主数据模型（核心字段）

| 字段组    | 关键字段                                                               | 来源       |
| ------ | ------------------------------------------------------------------ | -------- |
| 客户基础   | 手机号（唯一键）、姓名、性别、所在城市                                                | 三类合并     |
| 线索来源   | `lead_source_type`：1=经销商录入 / 2=垂媒 / 3=自媒体 / 4=厂商引流；`channel` 细粒度标签 | 来源 1/2/3 |
| 车型意向   | 关注车型 ID、配置、预算区间、对比车型                                               | 三类合并     |
| 行为轨迹   | 跟进记录（来源1）、内容互动（来源2）、官方活动参与（来源3）                                    | 三类合并     |
| 生命周期状态 | 新建/跟进中/已到店/已试驾/已订/已交付/战败                                           | 业务系统     |
| 时间戳    | 首次留资、首触时间、每次跟进时间                                                   | 三类合并     |
